# 0010. Two-factor authentication (TOTP)

- Status: accepted
- Date: 2026-11-19
- Ticket: #34

## Context

Login was password only. Two-factor authentication with an authenticator app (Google Authenticator and similar) adds a second factor.

## Decisions

1. **Opt-in per user, not mandatory.** Each user turns it on from "Seguridad". Mandatory 2FA would change the seed, the login flow of every test and the oral demo.
   - Rejected: mandatory for everyone. More secure, but it blocks the demo users until they enroll.
2. **TOTP (RFC 6238): SHA-1, 6 digits, 30 s, accepting one step before and after.** It is the only setup every authenticator app supports. The library is `otpauth`; the QR is generated by the API with `qrcode` and sent as a PNG data URL.
3. **Enrollment in two steps: `setup` then `enable`.** `setup` stores a new secret but `totpActivo` stays false, so an abandoned setup locks nobody out. `enable` needs a correct code, which proves the app has the secret.
4. **Login stays one endpoint and stateless.** With 2FA on and no `codigo`, the API answers `200 { requiereTotp: true }` and starts no session; the client sends email, password and code again. No intermediate token to store or expire. The login form shows an optional code field from the start (#38), because the user already has the account in the app: with the code typed, one request signs in; without it, a 2FA account gets the `requiereTotp` answer and the form asks for the code.
5. **A wrong code is a failed login.** It answers 401 `INVALID_TOTP` and counts against the per-IP limiter, which also limits guessing the 6 digits. The code is only checked after the password, so nothing is revealed to someone who lacks it.
6. **Disabling needs password and code.** Someone at an unattended open session cannot turn the protection off.
7. **Lost phone: the titular removes it** (`POST /api/usuarios/:id/reset-2fa`). It also ends the user's sessions.

## Consequences

- The secret is stored in plain text (`select: false`, never in JSON): TOTP needs it to compute codes, so it cannot be hashed. Protecting it is up to database access.
- A code can be reused within its 30 s window (no last-step tracking). It is accepted as the cost of keeping the model simple.
